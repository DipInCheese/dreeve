One Dreeve installation can serve several people. Every user gets their own **(sub)domain**, **data**
(database, photos, caches), **settings**, **admin login** and **Strava connection**.
Users never see each other's data.

This page sets it up behind a [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/),
so nothing on your network has to be opened up.

## Installation

You need a machine with Docker and a domain on Cloudflare.

```bash
mkdir dreeve && cd dreeve
curl -o docker-compose.yml https://raw.githubusercontent.com/DipInCheese/dreeve/feature/multi-user/docker/multi-user/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/DipInCheese/dreeve/feature/multi-user/docker/multi-user/example.env
chmod 600 .env
nano .env
```

Fill in `.env`:

```dotenv title=".env"
TZ=Europe/Brussels
TUNNEL_TOKEN=eyJh...

DREEVE_USERS=alice,bob

ALICE_URL=https://alice.example.com
ALICE_PASSWORD=a-long-password-for-alice

BOB_URL=https://bob.example.com
BOB_PASSWORD=a-long-password-for-bob
```

Start it:

```bash
docker compose up -d
```

That's it. Open `https://alice.example.com` and log in with username `alice`.

## Cloudflare Tunnel

1. In the Cloudflare dashboard, go to **Zero Trust → Networks → Tunnels → Create a tunnel** and choose **Cloudflared**.
2. Copy the token (the long value after `--token`) into `TUNNEL_TOKEN` in `.env`. You can skip the install instructions, the tunnel already runs in the `cloudflared` container.
3. Add a **public hostname** per user, all pointing at the same service:

   | Public hostname       | Service type | URL        |
   |-----------------------|--------------|------------|
   | `alice.example.com`   | HTTP         | `app:8080` |
   | `bob.example.com`     | HTTP         | `app:8080` |

Dreeve picks the user from the hostname. Any other hostname gets a plain "Not found".

:::tip
Your Dreeve pages are reachable by anyone who knows the address. To limit who can open them, put a
[Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/configure-apps/self-hosted-apps/)
application in front of the hostnames, e.g. allowing only your own email addresses.
:::

## Users and settings

* `DREEVE_USERS` lists the users: lowercase letters, digits and dashes, separated by commas.
* Every setting of a user starts with the user's name in capitals, dashes become underscores:
  user `bob-smith` uses `BOB_SMITH_URL`, `BOB_SMITH_PASSWORD`, ...
* `<NAME>_URL` (required) is the address the user opens Dreeve on.
* `<NAME>_PASSWORD` is the admin password, at least 12 characters. The admin username is the user's name,
  change it with `<NAME>_USERNAME`. Without a password the admin panel stays locked.
* **Every** [Dreeve setting](/getting-started/installation/#env) works per user with the prefix,
  e.g. `ALICE_IMPORT_MODE=stravaApi` or `ALICE_AI_API_KEY=...`. Without a prefix, a setting applies to every user.
* `TZ`, `TRUSTED_PROXIES`, `PUID` and `PGID` apply to the whole installation and can not be set per user.

Wrap values that contain `$` or `#` in single quotes: `ALICE_PASSWORD='pa$$word#1'`.

After changing `.env`, apply it with:

```bash
docker compose up -d
```

### Adding a user

Add the name to `DREEVE_USERS`, add `<NAME>_URL` and `<NAME>_PASSWORD`, run `docker compose up -d`
and add the hostname to the Cloudflare Tunnel.

## Security

* Passwords are hashed (bcrypt) when the app starts. The hash is stored in the user's data folder and is
  only recalculated when the password changes. The plain password is never stored by Dreeve, but it does
  stay in your `.env`: keep that file private (`chmod 600 .env`).
* Every user gets a random `APP_SECRET`, generated on first start and stored in their data folder.
  Both secret files are only readable by their owner.
* Each user's data, caches and login sessions are kept apart. A login for one user is not valid for another.
* The `cloudflared` container only receives the tunnel token.
* No ports are published on your machine; all traffic comes in through the tunnel.

## Data and backups

Everything lives in `./data`, one folder per user:

```text
data/
├── alice/
│   ├── storage/      <- database, photos and files
│   ├── build/        <- render cache
│   └── watch/        <- drop .fit/.tcx/.gpx files here to import them
└── bob/
```

Back up `./data` and `.env`, and you have backed up everything.

## Updating

```bash
docker compose pull && docker compose up -d
```

## Strava

Each user connects their own Strava account and needs their own Strava API application. Follow the
[Strava import](/importing/strava-import/) guide and set the application's *Authorization Callback Domain*
to the user's hostname, e.g. `alice.example.com`. Then add the user's settings:

```dotenv title=".env"
ALICE_IMPORT_MODE=stravaApi
ALICE_STRAVA_CLIENT_ID=...
ALICE_STRAVA_CLIENT_SECRET=...
ALICE_STRAVA_REFRESH_TOKEN=...
```

## Console commands

Console commands run for one user at a time, pick the user with `DREEVE_USER`:

```bash
docker compose exec -e DREEVE_USER=alice app bin/console app:strava:webhooks-create
```

## Logs

```bash
docker compose logs -f app
```

Each user's own logs are in `data/<name>/storage/files/logs/`.

## Advanced: settings in files

Instead of (or next to) `.env`, a user's settings can live in `data/<name>/.env`, without prefix.
Settings in the main `.env` win. A folder with such a file is a user even when it is not listed in `DREEVE_USERS`.
